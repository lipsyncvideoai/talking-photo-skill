# Talking photo with Lipsync

Create an image-and-audio lip-sync video using Lipsync V4. Require one user-provided image and one user-provided audio recording for a new task. If either is missing, ask the user to upload it and stop before requesting upload URLs or creating a task. Never automatically create a generation task to test this skill, its API key, or the workflow. If you decide a live workflow test is needed, stop and tell the user that one generation consumes credits; ask them to identify or upload exactly one image and one audio file for that test. Do not generate sample media, choose unrelated files, or proceed with the test before the user supplies those inputs. Accept local files or HTTPS URLs on product-controlled media hosts. Accept audio in MP3 or WAV format and images in JPG, JPEG, PNG or WebP format. Audio may be at most 40 seconds. If an input has another format, ask for a supported file or get the user’s agreement before converting it. For URLs, apply these media format requirements to the content, not just the URL suffix. This API does not accept video, subtitles, TTS, or a mode parameter.

1. Read `LIPSYNC_API_KEY` from the agent environment first. If it is absent on Windows, read `.lipsync-api-key.dpapi` in this skill directory using `scripts/api-key.ps1 -Action Read`; hold it only in memory and never print it. The file uses Windows DPAPI and is bound to the user and machine that saved it. If both are missing, guide the user to create a key on the [Lipsync subscription page](https://lipsync.video/subscription) and run `scripts/api-key.ps1 -Action Save` locally; do not ask them to paste it into chat. On other platforms, use the environment variable. Use the default origin in [API.md](API.md), unless the user explicitly supplies another deployment origin through `LIPSYNC_API_BASE_URL`.
2. Read [API.md](API.md). Use HTTPS for all requests. Send `Content-Type: application/json` with JSON API requests, including upload URL and task creation requests; upload file bytes to the signed storage URL according to its signing requirements. Use a non-Python HTTP client for API requests, such as PowerShell `Invoke-RestMethod` on Windows or curl on other systems, with `User-Agent: Lipsync-Talking-Photo/1.0`. Follow [upload and polling examples](references/upload-and-polling.md); accept local files or supported URLs, including mixed inputs. For local files, obtain upload URLs together and PUT both files before creating the task. Do not send the API key to storage or expose signed URLs.
3. Create the task once only after the user has supplied the image and audio for the requested video. Capture the returned task ID and actual `cost_credit` immediately. Do not automatically retry an uncertain create: it may have succeeded and a retry may charge again. If no task ID was returned, explain that the outcome is unknown and ask the user to check existing jobs before retrying.
4. Unless the user requests submission only, poll the existing task every 10 seconds for up to 30 minutes or the user's deadline. Query the task ID with the same non-Python HTTPS client, and retry transient query failures within the deadline. Do not start a new task to retry a query. On success provide the task ID, status and video URL. On failure provide the public error. At the deadline provide the task ID and last known status; do not call processing a failure.
5. If the API key is invalid, direct the user to check or regenerate it; explain insufficient credits for HTTP 402. Respect `Retry-After` for 429. Distinguish API upload URL errors from storage PUT errors. For a 403, investigate the client, proxy and access controls; the PowerShell and curl procedure in [upload and polling examples](references/upload-and-polling.md) is an alternative. A failed PUT must stop task creation. Never print the key or signed URLs.

Use [upload and polling examples](references/upload-and-polling.md) for local-file upload and manual polling examples, and [API.md](API.md) for the exact API contract. Report server-provided costs rather than calculating them.
